# OkamiUNI 0.5.5 — Invites without copies, agents and mail fixes

[Português (Brasil)](https://github.com/OkamiOps/okamiuni/blob/v0.5.5/docs/releases/v0.5.5.pt-BR.md) · **English**

Released October 13, 2026. App version **0.5.5**, build **10**.

## What's new

- **Invites no longer duplicate in Google Calendar.** Accepting or answering an invite still sends the iTIP `METHOD:REPLY` to the organizer, but OkamiUNI no longer writes the event to the system calendar. Before, each accepted invite — and each reschedule by the organizer — created a new event owned by you, with no guests, "Sem local definido" as location and a fresh Meet link. The invite now matches the original Google already shows by its iCalendar UID, even after a time change, and the card says "In calendar".
- **Agents:** the assistant gets native draft tools and integrates provider-neutral external agents over ACP and A2A.
- **Reader:** HTML bodies behind a tracking pixel or sent as a bare fragment no longer open as source; tracking pixels stay blocked even with remote images allowed; protocol-relative images load over HTTPS; late images no longer clip the end of the message.
- **Mail:** recipients, cursor-placed signatures, HTML fragments and missing attachments repaired; the detached message window uses the complete reader; the composer keeps the formatting selection and closes after an accepted send.
- **Calendar:** event dates survive midnight and day rollover; removing an imported cancelled occurrence sticks.
- **Dashboard:** current inbox state, current and proactive priorities, actionable AI briefing.
- **ChatGPT subscription:** direct OAuth sign-in fixed, and the model list comes from the live catalog.

## Existing copies

Copies created before this version stay in Google Calendar. They are organized by you, have no guests and show "Sem local definido" as location; delete them there.

## Validation

- `UNICore`: **1,068 tests passed**, including three new tests covering accept, reschedule with the Google original present, and invite updates — none may write to the system calendar.
- `UNIShell` and `UNISync` carry failures that also occur on the previous commit without this change (UI tests that vary run to run, an RSVP click test and an assistant destination string).
- Release build: **BUILD SUCCEEDED**.
